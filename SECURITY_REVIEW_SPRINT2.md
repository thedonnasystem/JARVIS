## Open risks (not fixed; none downgraded)
- R1 (Major, accepted limitation): the evidence check proves a citation exists in the mission's own output, not that the source supports the claim. Stronger than first documented: the engine does not keep the fetched page content at all (only the model's final text), so the check compares claims against the researcher's paraphrase, not the page, and cannot tell injected web text from genuine text. Design for the fix: `EVIDENCE_VERIFICATION_DESIGN.md`. Mitigation today: the check only ever downgrades; a human reads verified missions before any money or external action.
- R2 (Major, owner decision): email double-authorization halves the daily send allowance and can leave a posted email unmarked. Reproduced; fix prepared, not applied: `DOUBLE_AUTHORIZATION.md`.
- R3 (Minor): a lone decorated `## Verified - yes` line counts as YES when it is the only label in the reply.
- R4 (Minor): `hq_mail.live()` requires mode `live`, which the database constraint forbids, so the automated sender can never send (safe, but must be resolved before enabling it).
- R5 (Minor): crash between recurrence claim and child creation leaves `spawned="claiming"`; the chain waits for the owner (chosen over a duplicate).
- R6 (Minor): a verified mission with `FACTS` stores them in company memory; facts come from model output over web text (same untrusted-content risk as R1).
